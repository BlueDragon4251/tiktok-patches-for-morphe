# Native theme surfaces on 46.7.3 and 47.1.3

The connected Android 16 device reproduced empty long-press/share sheets, a
missing profile follower field, invisible notification filters, and white
System notifications cards with Arctic Blue. The original installed baseline
identified BlueIT 1.2.2; its local development source was disabled.

The theme patch now owns the verified TuxNavBar header, System notifications
roots and TuxSheet content. Native lifecycle bodies, real receiver/return
registers, cardinality and mutation contracts remain checked for both pinned
APKs. Native-owned roots avoid the competing dynamic-list pass. Bounded styling
handles late children, neutral text spans, native icon tint and wrapped card
fills while retaining media, functional colors, drawable shape and state.

The generic TUX resolver accepts only a converted value that carries the actual
mapped color. Resource IDs, flags, dimensions and multi-value arrays retain their
native fallback. Theme resolution must also preserve a missing native value:
recognizing a page token does not establish that its Context has a TUX theme.
The resolver now requires a stock color before caching a role or returning an
override. The regression tests use a real resolved theme attribute and separately
exercise the unresolved page token and uncalled converter.

## Verification and device evidence

### October 30: confirmed bytecode cause

The original 47.1.3 APK and a full BlueIT comparison excluding only Theme engine
both displayed complete native menus and the follower count with the same app
data and signing key. The unresolved-value guard alone did not fix the themed
build. Comparing serialized instructions then exposed incorrectly relocated
internal labels: all four TUX null fallbacks branched to `return-object null`
instead of the native continuation. The avatar gradient guard's valid branch
pointed into an instruction operand, producing ART's `Unexpected instruction:
unused-f5` once native colors were restored.

`ContractInstructions` now uses label-aware insertion for internal as well as
external labels. Trailing continuation labels receive an explicit NOP anchor.
Existing native branch/handler locations and semantic mutation contracts remain
preserved. Tests exercise forward/backward branches at entry and nonzero offsets,
plus a trailing continuation. A separate reproduction verified relocation with
both Patcher 1.15.1 and 2.0.1. The rebuilt 47.1.3 DEX now has the correct TUX
offsets (+3) and avatar continuation (+4).

A private five-branch control restored the complete long-press menu, follower
count/label, and notification filters on the connected phone. The full a7c5fc8
build subsequently displayed complete, dark long-press and Share menus with
readable labels. TuxSheet's verified return is its RadiusLayout content, rather
than the dismiss backdrop; that content now receives a theme fill even when its
native Drawable is null. App data were retained throughout.

Stateful text with transparent default states, unused background tints, native
bitmap navigation glyphs, and TuxIconDrawables wrapped in layers now have explicit
handling. The 1001f26 device build restored navigation glyph visibility. A bounded
private probe then confirmed that the remaining dark Bio label had light colors
in its outer TextView, Paint and Layout: its native ReplacementSpan instead draws
a detached TuxTag View. That view was outside the hierarchy walk. Styling now
visits only View/Drawable-typed fields on ReplacementSpans, with depth/node limits,
and restores their exact native palettes in Default. Native span identities,
measurement and bounds remain unchanged. No text contents were logged.

The connected phone also exposed a compact RelativeLayout inbox header outside
TuxNavBar, plus a wrapped white hint-card fill. The identified list title now
anchors a bounded header pass, and flat native wrappers retain their shape while
receiving a themed fill. Default restores the original wrapper.

The full f4ee7c4 build was installed through Shizuku on October 30 at 10:05:34,
with the existing key and retained app data. Share and long press opened complete
dark menus; follower count/label, Bio, inbox header actions and hint-card fill were
readable. TikTok settings were themed and BlueIT Services had its own category.
Caption text was also visible after switching to TikTok Default and cold-starting;
Arctic Blue was then restored. A short System notifications open/scroll sample
rendered 417 frames with 12 janky frames (2.88%); this is not a long-session benchmark.

The separate Activity page still exposed black inline account/time spans. Its
dynamic text pass now retains its semantic foreground choice while applying the
same span-aware styling and Default restoration as the owned native roots.
Late replacement of a child inside an already tinted LayerDrawable also refreshes
the native tint writer, rather than retaining an earlier null tint capability.

The Activity filter dropdown uses a separate native PopupWindow. Its menu recycler
is now identified through the notification FilterViewModel, GroupFilterViewHolder,
native PopupWindow ancestry, original super show call, and unique recycler field.
The hook runs before the verified void return, with a proven receiver alias and
dead scratch register. It styles that menu field only, retaining the separate dim

SHA-verified 46.7.3 reference adds five method/class digest and hook identity entries;
all pre-existing reference values are unchanged.

## Installation details

Android killed the original full Manager build with LOW_MEMORY. Heavy patching
therefore runs on the PC (37 BlueIT patches plus Change installer source); the
Manager applies Disable Play Store updates and its dependencies once, then signs
with its existing key. The PC input preserves the original version code so this
last pass records the real TikTok version. Reapplying update protection twice is
not a valid reproduction procedure. The Manager's installed record describes its
last one-patch pass, rather than the complete patch footprint already in its input.

No app data were cleared and TikTok was never uninstalled. Exporting the existing
key did not assign a password; temporary exported key copies were removed. The
final tested BlueIT build is installed. The local BlueIT source points to d37f7cc
and is enabled alongside official 2.0.0-dev.1; remote BlueIT 1.2.2 and Metra remain
disabled. Using the existing stock 47.1.3 APK, the saved selection was restored to
37 BlueIT plus Change installer source and Disable Play Store updates (39/42),
with Clone app unselected. No additional patch/install run was started. The
temporary prepatched input on the phone was removed, normal screen-off behavior
was restored, and the phone was returned to its home screen. Device screenshots,
process logs and APKs remain private and outside this repo. No release or merge
was performed; the test build retains development metadata 1.3.0-dev.5 and is
identified by its source commit.
